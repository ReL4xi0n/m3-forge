## What changed between rounds

- After round 1: the subset icon font ended off a 4-byte boundary and Chromium rejected it (icons
  showed as their names); the screenshot step skipped without Playwright, so the model never saw
  its render (now falls back to an installed Chrome or Edge); checklist recipes for visible
  requested parts, no overlaps, one action per view, theme-aware placeholders.
- After round 2: the report must list every requested item and where it is visible, and every
  problem found in the screenshots with its fix; layout and accent recipes; native controls follow
  the theme (`color-scheme`); classic M3 scoping for Expressive-only component styles.

## Round 4 (owner-approved extra round, composition focus)

Changes before the round, all in the shared core so Flutter and Compose use them too:
- `references/core/layout.md`: a canonical-layout table (feed, list-detail, supporting pane, single
  pane) chosen by what the screen does and by window width, and rules for filling the window (panes
  run to the bottom, no blank column, grids fill their pane).
- `references/core/typography.md`: hierarchy recipes per screen type (product detail and card,
  list, form, media player, dashboard); neighboring levels differ in two of size, weight and color.
- `references/core/composition.md` (new, always read): placement, grouping, spacing rhythm and
  emphasis, written in our own words from the owner's private reference screenshots.
- Web part `shapes`: the 35 Compose `MaterialShapes` as CSS masks, geometry generated by running the
  official material3 1.5.0-rc01 code on the JVM ([impl:], Apache-2.0, NOTICE).
- No-Node runs now hide every JavaScript runtime (node, bun, deno and their shims).
- Always-read core references re-measured: 14,972 tokens for the 8 files (under 15K, after
  trimming duplicate lines); CHECKLIST.md adds 2,011 tokens on top.

**Caveat.** The judge v2 anchors are the same private reference screenshots the composition note
was written from. Scores on composition-related items can rise because the skill learned the
judge's reference style, not only because the screens got better. Treat round 4 gains with that in
mind; the Phase 4 hold-out and the owner's visual check are the guard against it.

### Remaining gaps (judge, round 4)

- Requested parts still missing even with the step 5 list: the podcast mini-player, the plant-shop
  empty-result state, the expense confirmation summary (component-choice 1 in two cells).
- Error and stock notes read as saturated salmon. The code uses `error-container` as the checklist
  asks, but the color script follows the MCU 2025 spec, whose light `errorContainer` is the
  highest-chroma tone up to 90 of the error palette (seed #2F6F5E: `#fa746f`), not the pale tone 90
  of the 2021 spec. This needs an owner decision on the color spec, not a wording change.
- Desktop composition: the podcast player's controls column and the plant-shop filter panel still

- Product cards: round 3's judge asked for a stronger price, round 4's judge found the larger
  price competing with the name.
- No round 4 cell used the new shapes part.
